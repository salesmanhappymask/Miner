Quarry swarm v94: small Standard worker disks

Publish all files in this archive at the repository root before updating the RM and Master Foreman. Run their local update commands to install v94, then run prep and choose Standard. Prepare fresh disks because the v92 Standard disk layout is too large for some configured server disk limits.

Standard disks now contain only startup, a 1450-byte worker installer. On an unconfigured worker, it downloads version, common, startup, and bootstrap into memory, checks the version, and runs the bootstrap. The bootstrap installs the downloaded startup and common locally. On subsequent reboots, the disk installer starts the configured turtle's local startup instead of commissioning it again. HTTP access to the configured raw Git repository is required when a worker first boots.

Initial Setup still writes only update to the disk. A prep disk now checks available space before writing and reports both required and free bytes if the disk is too small. A failed readback names the file and reports remaining disk space.

The RM/Master Foreman update flow and the mining runtime otherwise follow v92. Version and radio protocol are 94. Updating either administrator wipes its local state, so the swarm must be recommissioned with v94 workers.


v94 changes: administrator update now deletes every pre-existing root file and directory except the running updater and temporary verified staging directory, then recreates updater.cfg and the selected role installation. Old error logs, recovery logs, state files, node.cfg, release directories, and other leftovers are removed. Master Foreman world_anchor is retained in memory across the wipe and rewritten afterward. Foreman-1 seed refueling now probes all 16 turtle slots directly with turtle.refuel(0), so valid fuel is recognized even when the Narcissistic inventory peripheral metadata is unavailable or stale.
